# 项目标签设计

## 目标

为已发现的本地项目添加轻量、持久化的多标签能力。标签显示在项目目录中，并参与现有项目搜索，帮助用户在项目较多时快速辨识和定位项目。

## 范围

- 每个项目最多保存 8 个标签。
- 标签名称去除首尾空白后不能为空，最多 20 个字符。
- 同一项目的标签按不区分大小写的方式去重。
- 项目行显示标签，并提供键盘可访问的行内编辑入口。
- 现有项目搜索同时匹配项目名称、路径和标签。
- 扫描、重新扫描和项目更新不得清除已保存的标签。

本次不实现标签颜色、全局标签管理、批量编辑、标签重命名或独立筛选器。这些能力没有被当前 TODO 要求，现有搜索已覆盖按标签定位项目的主要场景。

## 数据模型

新增 `project_tags` 表：

```sql
CREATE TABLE project_tags (
    project_id INTEGER NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
    name TEXT NOT NULL COLLATE NOCASE CHECK (length(name) BETWEEN 1 AND 20),
    PRIMARY KEY (project_id, name)
);
```

数据库版本递增。迁移保持幂等，已有项目无需转换数据。读取项目列表时一次查询项目与标签并在 Rust 层组装，避免前端逐项目请求。写入时使用事务整体替换单个项目的标签，确保失败时不留下部分结果。

## 后端与 IPC

Rust `Project` 增加 `tags: Vec<String>`。数据库提供一个设置单个项目标签的方法，负责裁剪、校验、大小写不敏感去重和事务写入。

新增受限的 Tauri Command：

```text
set_project_tags(project_id: i64, tags: Vec<String>) -> Project
```

命令返回更新后的项目，前端可直接替换本地状态。接口只允许结构化标签数据，不开放任意 SQL 或 Shell 能力。

## 前端交互

TypeScript `Project` 增加 `tags: string[]`。项目目录在路径下方显示紧凑的标签胶囊；无标签时不占额外高度。

每个项目行增加“编辑标签”按钮。点击后在该行下方展开单个文本输入框，用户以逗号分隔标签，保存或取消。保存时前端做即时格式提示，后端仍是最终校验边界。编辑期间项目选择和收藏继续保持原行为，busy 状态统一禁用相关控件。

现有搜索计算属性增加 `project.tags.some(...)`，不增加新的筛选状态或全局标签仓库。

## 错误处理

- 空标签、超长标签或超过数量限制由 Rust 返回中文错误信息。
- 数据库写入在事务内完成，任一步失败则全部回滚。
- 前端通过现有 `runAction` 和操作中心展示失败，不增加新的通知机制。
- 保存失败时保留编辑内容，便于用户修正。

## 验证

- Rust 数据库测试覆盖迁移、保存、替换、去重、限制校验和重新扫描后保留标签。
- 前端组件测试覆盖标签展示、编辑、保存、取消、busy 禁用和事件参数。
- composable 测试覆盖更新本地项目状态；搜索测试覆盖名称、路径和标签匹配。
- 运行 `npm run test:frontend`、`npm run check`、`npm run build`、`npm run test:rust`、`cargo fmt --check` 和 `cargo clippy -- -D warnings`。
- 实际启动桌面应用，检查 960px、1280px 和最大化窗口下的标签换行、按钮状态、键盘焦点和整体风格。

## 完成标准

- 用户能够为项目新增、修改和清空标签，重启应用后数据仍存在。
- 标签可见且可被现有搜索命中。
- 项目扫描不会覆盖标签。
- 自动化验证、桌面界面检查和重大项代码审查均通过。
- `docs/TODO.md` 的“项目标签”更新为完成，并形成可回滚的独立提交。
